# Solo mode

## solo-mode

- **Control:** title `Solo mode`, a segmented control `Off` / `Whole folders` / `Weaver's files only` (the same component as `Theme`, a radio group for assistive technology), with the note `Applies only to this working copy: other clones start with it off.` under it. It is not in the settings schema and is never stored in `settings.json`: it shows the project's state and sends changes to the backend.
- **Places:** first in the `Project` group of Settings, before `Update skills`; in Get Started between the list of agent files and `Initialise`.
- **Settings, saving:** at once on choice, no confirmation, also when turning it off. While a change runs the control is disabled. A failed change shows `Could not change Solo mode: <reason>.` under it in the error colour and puts back the project's value.
- **Settings, not initialised:** disabled on `Off`, with `Choose Solo mode when you initialise the project.` under the note.
- **No git:** disabled on `Off` in Settings and in Get Started, with `Solo mode needs git: git was not found.` or `Solo mode needs git: this folder is not in a git repository.` (the other reasons of `requirements/rules#solo-mode` as `Solo mode needs git: <reason>.`).
- **During a merge:** while a merge is in progress (`requirements/ui#solo-merge`), the control is disabled in Settings with `Finish or abort the merge in progress first.` under the note.
- **On:** under the note, in the warning colour with `TriangleAlert`: `Weaver's files are not versioned anywhere: losing this working copy loses them.`
- **Not excluded:** in the warning colour with `TriangleAlert`, in Settings only: `Solo mode is on but cannot exclude Weaver's files: <reason>.` when git is missing or the folder is no longer in a repository, otherwise `Weaver's files may not be excluded from git: <reason>.` The control stays usable.
- **Tracked files:** in Settings, while Solo mode is on and the list is not empty, an `Alert` (warning variant) with `Git still tracks <N> of Weaver's files: their changes still go into commits.` and below it the relative paths, monospace, scrolling past 8 lines. No action to stop tracking them. The list is asked for each time the Settings view is shown and replaced by the result of every change; while it loads, the earlier list stays.
- **Get Started:** `Off` is chosen at first and the choice lives only in the screen. With `Whole folders` or `Weaver's files only` chosen, the text becomes `Weaver will create a .weaver folder that describes this project. With Solo mode its files stay only in this working copy and never go into a commit.` and the warning of **On** shows under the control. `Initialise` and `Overwrite and initialise` both send the choice. A Solo mode failure shows as `Could not initialise: <reason>.`
- **Accessibility:** the note, the warnings and the reason a control is disabled are its description for assistive technology (`aria-describedby`); the list of tracked files is a labelled region; a change of the warnings is announced (`aria-live="polite"`).

## solo-merge

- **Button:** `Merge`, `outline` Button with the icon `GitMerge`, in the Board header to the left of `Scan System`, only while Solo mode is on; tooltip `Merge another branch into <current>`. Disabled reasons, the first that holds (`requirements/rules#solo-merge`, **Availability**): `The agent is working`, `A merge is in progress`, `Merge needs git: <reason>`, `Git is in the middle of a merge, rebase or cherry-pick`, `Not on a branch`, `Commit or stash your changes first`. The reason is the tooltip and the accessible description of the disabled button.
- **Dialog:** title `Merge a branch`; a `Search branches` field filtering a list (a `Command` list: local branches, then remote ones, under the headings `Local` and `Remote`); arrow keys move, Enter chooses. Once a branch is chosen: `Merge <branch> into <current>?`, and, when git still tracks some of Weaver's files, an `Alert` (warning variant) `Git still tracks <N> of Weaver's files: their changes go into the merge commit.`; buttons `Merge` (primary) / `Cancel`. While the merge runs, `Merge` shows a spinner and both buttons are disabled; the Dialog closes when git answers. With no other branch, the list shows `No other branch`.
- **Notices** at the top of the Board (`requirements/ui#work`, **Details dialogs and notices**), each with a close button: `<current> is already up to date with <branch>.`; `Could not merge <branch>: <first line of git's error>.`; `Could not merge <branch>: it would overwrite files that Solo mode keeps out of git.` followed by the paths, monospace; `Could not merge <branch>: git did not finish the merge within 2 minutes.`; `The merge of <branch> ended without a commit: Weaver forgot it and did not scan.`; `Could not abort the merge: <first line of git's error>.`
- **Merge banner:** while a merge is in progress, an `Alert` above both columns and above the notices, with the icon `GitMerge` and no close button: `Merging <branch> into <current>: <n> files with conflicts. Resolve them here or by hand, then commit the merge in git.`, or, with no conflicts left, `Merging <branch> into <current>: no conflicts left. Commit the merge in git to finish.` Its actions, on its right: `Resolve with the agent` (primary, icon `Sparkles`, only while some file has conflicts; disabled with `The agent is resolving the conflicts` while the merge conflicts job has not ended) and `Abort merge` (outline, destructive text).
- **Abort:** confirmed with `Abort the merge of <branch>? Every change of the merge, conflict resolutions included, is lost.`, `Abort merge` (destructive) / `Cancel`; disabled with `The agent is resolving the conflicts` while the merge conflicts job has not ended.
- **Accessibility:** the banner is a `region` named `Merge in progress`; a change of its text is announced (`aria-live="polite"`); disabled reasons are the description of their control (`aria-describedby`).
