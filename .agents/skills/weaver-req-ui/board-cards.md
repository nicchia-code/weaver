# Board decision cards

## proposal

- Card, top to bottom: id, title (at most 3 lines, then `…`) and kind mark; badges; files line; Tasks line; controls.
- Kind mark: outline badge `setup` or `import`; an ordinary change has none; a resolution is the yellow card below.
- Badges, in order: `stale` (amber), `refining` (blue, a refinement job works on it), `refinement interrupted`, `blocked` (red), the chosen model (outline, icon `Cpu`). `blocked` is a Popover button listing every blocking reason on its own line; a reason about a required Proposal names it and says `is still being written`, `was rejected`, `was discarded`, `is missing`, `is not approved yet` or `forms a cycle`.
- Files line: `<n> files` with a muted `+a ~c −r` (added, changed, removed); paths, relative to `.weaver/`, are in the details.
- Tasks line, only when it carries Tasks: `Creates <n> Tasks` (code-removal Tasks included) and its label as a badge in the label colour (see `task`).
- Controls: `Approve` (primary), or `Refine` in its place (see below); `Reject`, a split button whose menu has one item, `Rework with feedback…` (absent once reworked); `View requirements`, only when its focus would have at least one step; last, the model control (icon `Settings`, only when it carries Tasks), pushed to the card's right edge, also when the row wraps; the other controls stay on the left.
- `Approve` disabled reasons, in order: `The agent is still finishing`, `A run is in progress`, `Being refined`, then each blocking reason. On every stale Open Proposal, whatever its kind and whatever else blocks it, `Refine` replaces `Approve`, enabled also during a Run; it is disabled only by `The agent is still finishing` and, for a resolution none of whose Drifts is still open, by `None of its Drifts is still open`. The other blocking reasons stay listed in `blocked`. Tooltip `Refine on the current Model, then approve`, or `Refine on the current Model` when a required Proposal is still being written or not approved yet. `Reject` and `Rework with feedback…` are disabled only by `The agent is still finishing` and `Being refined`.
- `Refine` tells that a click starts the agent: text and accessible name `Refine`, icon `Sparkles`, solid yellow (background `yellow-500` in light and `yellow-400` in dark, one shade darker on hover, text `zinc-950`), no confirmation. It shows wherever the card's controls show, the details dialog included, and in the details of a Drift (see `drift`).
- `Reject` opens a Dialog with an optional `Reason` Textarea and `Reject` (destructive) / `Cancel`. `Rework with feedback…` opens a Dialog with a `Feedback` Textarea and `Rework` / `Cancel`; blank feedback asks `Rework without feedback?` first.
- The model control opens a Popover with a Select of omp's models (the Settings list), `Use the Settings models` first; a choice applies at once.
- A Draft left half-way by a refinement keeps its card with the badge `refinement interrupted` and only `Refine` (tooltip `Continue refining, then approve`, or `Continue refining` when a required Proposal is still being written or not approved yet; disabled as on an Open Proposal) and `Discard` (destructive, confirmed).
- **Chat Draft:** a Draft with `chatWriting: true` has a card in Backlog, in card order, with the layout of an Open Proposal of its kind (files line, Tasks line with the label, resolution rows), updated as Chat writes it, plus the outline badges `draft` and `Chat` first. Its only controls are `Open Chat` (outline, `MessageSquare`), which shows the Chat view, and `Discard` (destructive), which asks `Discard this Draft?` / `Its files and Tasks are thrown away.` with `Discard` (destructive) and `Cancel`, focus on `Cancel`. While a turn of Chat is in progress, `Discard` is disabled with `The agent is still finishing`. The details dialog shows the same controls, then `Ask more`.
- No other Draft has a card.
- Resolution card: same layout, 3 px yellow left border and light yellow tint, mark `resolution`, then one row per listed Drift: id, title and decision (`Fix the code: option <n>` with the note muted, `Change the Model`, `Let it be`). Rows open the Drift's details. Lines with nothing to say are omitted.
- Details dialog: id, title, kind, badges, rendered body, `Requires` (each Proposal with its state), files grouped as added, changed and removed, `Tasks it creates` and `Code-removal Tasks`, then the card's controls followed by `Ask more` (see `ask-conversation`), which the card itself never shows.
- Task lists in the details dialog: one compact row per Task holding only its title; no ref chips and no `technical` badge. Each row of `Tasks it creates` is a button that opens a nested Dialog over the details dialog with the Task's title and its rendered body (`No description.` when blank), no refs and no badges; `Esc` or `Close` closes only the nested Dialog and the focus returns to the row. Code-removal rows use the same list style but are plain text, not controls, and render the reference in their title as inline code, not with literal backticks. When the details dialog closes, the nested Dialog closes with it.

## drift

- Card: compact, 3 px red left border; id, title (at most 3 lines), badges; then `Resolve` (primary) and `Dismiss Drift` (outline).
- Badges: `recurring` (tooltip names the earlier Drift), `resolving` (a resolve job works on it or a resolution in Draft or Refining lists it; tooltip `An agent is resolving this Drift`), `prepared` (valid prepared question; tooltip `Resolve asks the prepared question at once`), `merge` (outline, a Drift from a merge; tooltip `Found by the scan after a merge`). The details dialog shows the same badges.
- `Resolve` disabled reasons, in order: `The agent is still finishing`, `A run is in progress`, `A merge is in progress`, `Being refined` (its attached Proposal is Refining), `This Drift is being resolved`, `Another resolution is being written` (a resolution in Draft or Refining), `Proposal <id> resolving Drifts awaits a decision` (a resolution Open, or a Draft left half-way by a refinement).
- `Dismiss Drift` confirms with `Dismiss <id>? Nothing changes in the code or in the Model.`, `Dismiss` (destructive) / `Cancel`. Disabled reasons: `The agent is still finishing`, `Being refined`, `This Drift is in a resolution`.
- Details dialog, in order: id, title, badges; referenced elements and sections as chips (each opens a single-ref focus); `What happens` and `What should happen` side by side (stacked below 640 px of dialog width); `Fix options`, numbered, the first marked `recommended`; `Where in the code`, one row per file with its line when given and `Open in editor`; the origin Task and the repeated Drift, when known; the attached Proposal, if any, with title, its state (`Draft`, `Refinement interrupted`, `Open` or `Refining`), the `stale` badge when stale, rendered body and files.
- Fix decision, in the details: a RadioGroup of the fix options (recommended preselected), an optional `Note` Textarea and `Fix the code`. Without options the RadioGroup is replaced by `No code change can respect both the Model and the Requirements.` and there is no `Fix the code`. With an attached Proposal, `Accept Proposal`; disabled with that Proposal's blocking reasons when it cannot be approved. When the attached Proposal is stale and Open, `Refine` replaces `Accept Proposal`, with the tooltip `Refine on the current Model`, disabled only by `The agent is still finishing`. When it is a Draft left half-way by a refinement, `Refine` (tooltip `Continue refining`) and `Discard` (destructive, confirmed as on the Proposal card) replace it. While it is Refining, `Accept Proposal`, `Fix the code`, `Resolve` and `Dismiss Drift` are disabled with `Being refined`. `Resolve`, `Dismiss Drift` and then `Ask more` (see `ask-conversation`) are in the footer. `The agent is still finishing` comes first on every decision control.
- Merge Drift, in the details: `recommended` marks `Accept Proposal` instead of the first fix option; the fix options stay numbered without the mark and none is preselected, so `Fix the code` stays disabled until one is chosen.
