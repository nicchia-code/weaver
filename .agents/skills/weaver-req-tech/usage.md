# omp usage

## usage

- **Reading:** `omp usage --json` (table in `requirements/tech#omp`), run by the Rust backend only while omp is Ready; never with `invalidate`, `reset`, `--history` or any other action that writes omp's state. One reading runs at a time app-wide: an opening, a `Retry` or a tick while one runs waits for that one. Weaver relies on omp's own cache of the providers' answers and never asks a provider directly.
- **When:** at each opening of the Usage dialog, at each `Retry`, and on one app-wide timer (`time.USAGE_REFRESH_DUE`): a reading starts as soon as omp is Ready with no reading since the app started, then 5 minutes after the start of the last reading, whatever started it. A tick is skipped, not delayed, while omp is not Ready or no Weaver window is on the screen (every window hidden in the background or minimised); the next one is counted from the skip. The timer lives in the backend, never in a window.
- **Parsing:** from `reports[]`: `provider`, `fetchedAt` and each of `limits[]` with `label`, `window.resetsAt`, `amount` (`used`, `limit`, `usedFraction`, `remainingFraction`, `unit`) and `status`; from `accountsWithoutUsage[]` and `disabledCredentials[]`: `provider`. Unknown fields are ignored; output that is not valid JSON of this shape fails with the reason `the agent did not return valid usage`.
- **Providers:** only the fixed list of `requirements/tech#omp-setup`, and of it only the connected providers; reports of other providers are dropped. A connected provider without a report is `No usage data` when it is in `accountsWithoutUsage`, `Login expired` when it is in `disabledCredentials`, otherwise `Not reported by omp`. Email, account, organisation and other identity fields are never parsed, kept or sent to the interface.
- **Used fraction**, computed in `weaver-core`: `usedFraction`, else `used / limit` when `limit` is above 0, else `used / 100` when the unit is `percent`, else `1 − remainingFraction`, else unknown; clamped to 0–1 for the bar. **Status:** omp's `status` (`ok`, `warning` = almost used up, `exhausted` = used up); without it, almost used up from 0.8 and used up from 1 of the used fraction.
- **Summary,** computed in `weaver-core` from the last result: the limit closest to being used up among the shown providers, that is the one with the worst status (used up, then almost used up, then the others) and, within it, the highest known used fraction; ties go to the earliest reset, then to the order of the providers and of their limits. Limits with an unknown used fraction count only when no other limit exists, and then the summary shows no percentage and no bar. It carries the limit's name, its used fraction, status and reset, or none when no shown provider has a limit.
- **Last result:** one app-wide value in the backend's memory, tagged with the omp path it was read for, never written to disk; it is replaced only by a successful reading and dropped when the omp path changes. A reading that ends after its dialog closed, or that no dialog asked for, still replaces it. Every window receives it, with its summary, through the backend's events; the interface keeps no copy of its own.
- **Waiting for omp:** a dialog in Waiting for omp starts a reading when the app-wide omp state becomes Ready.
