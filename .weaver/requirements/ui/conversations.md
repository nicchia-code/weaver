# Jobs and conversations

## job
- **Jobs view:** under the view header (`requirements/ui#General`, title `Jobs`, no controls), which spans both panes, the project's jobs listed on the left (~300 px, resizable 240–420 px), the selected job's conversation, or the selected sub-agent's, on the right. The headers of the right pane (a sub-agent's path, `Back to questions` of an Ask more conversation) stay inside that pane, below the view header. Empty list: `No jobs yet`. Ask more conversations are listed among the jobs, with their own row and conversation (see `ask-conversation`).
- **List spacing:** 12 px of space between the top edge of the jobs list and its first row, inside the list's scrolling content, so it scrolls away with the rows; no added space below the last row.
- **Fixed names**, set at creation: `Setup`, `Design`, `Import`, `Scan`, `Run T3` (short number, else permanent ID), `All tasks`, `All tasks · <model>`, `Resolve D3`, `Rework P3`, `Refine P3`, `Merge conflicts` (kind `merge`); the scan after a merge is `Scan` too. Equal names are told apart by started time.
- **Row:** name (semibold), kind in secondary text (`setup`, `design`, `import`, `scan`, `run`, `resolve`, `rework`, `refinement`), state badge, started time, running time, and the latest note on a second line truncated with `…` (full text in the tooltip).
- **Sub-agent list:** under the selected job's row, and only under it, an indented list of its sub-agents opens; selecting another job closes it and opens that job's. A job with no sub-agents shows no list.
  - Its direct sub-agents in launch order, across all its `task` calls; under each one, indented one more step, the sub-agents it started, in launch order, at any depth. omp's advisors never appear.
  - Each row, one line: `Bot`, omp's name for it truncated with `…` (full name in the tooltip), state as icon and text as in **Sub-agents** below. When siblings have the same name, each of them adds its started time `HH:MM` in secondary text.
  - A row is a button: it shows that sub-agent's conversation on the right and gets `aria-current`; the job's row stays marked as its parent, and selecting the job's row shows the job's conversation again.
  - The list stays, with its states, while a finished job stays listed, also after its session was reloaded; removing the job removes its sub-agents.
- **Badges**, always with text: `queued` (outline), `running` (blue, spinning `Loader`, static under reduced motion), `waiting` (warning, `MessageCircleQuestion`), `suspended` (outline, `Pause`), `done` (green, `Check`), `failed` (error, `X`), `stopped` (muted, `Square`).
- **Times:** started `HH:MM` today, else `D MMM HH:MM`. Running time counts from the session start (none while queued), ticks every second while working, freezes at the end: `45s`, `4m 05s`, `1h 12m`.
- **Order:** waiting, then running, queued, suspended (each newest start first), then finished jobs, latest end first. Ask more rows `waiting` and `running` sort with the jobs in the same state; `idle` ones come after the suspended jobs, newest opening first.
- **Retention:** a finished job stays listed until removed with its row's `X` (no dialog) or the window closes; only the 30 latest finished jobs are kept. Working jobs have no `X`.
- **Conversation:** entries top to bottom, message box pinned at the bottom. The view follows new text unless scrolled up; then `Jump to latest` (`ArrowDown`) appears. Nothing scrolls sideways: tables and code scroll in their own box.
- First entry: Weaver's one-line instruction, shown as a message labelled `Weaver`. Developer messages: right-aligned boxes on the secondary background, plain text. Agent messages: full width, no box, Markdown with the shared renderer; reasoning in a collapsed `Thinking` block.
- **Tool calls:** one compact row each: icon by kind (read `FileText`, search `Search`, command `SquareTerminal`, edit `FilePen`, sub-agent `Bot`, other `Wrench`), omp's title on one line truncated with `…`, status icon (`Loader`, `Check`, `X` in error colour). A row whose text does not fit is a disclosure button (`ChevronRight`/`ChevronDown`, `aria-expanded`) opening the full command (without leading `$ `) or full title in a monospace box, ~12 lines then scrolling. Rows never show results or output. Rows start closed.
- **Sub-agents:** under omp's `task` row, indented, one line each in omp's order: `Bot`, omp's name for it, state as icon and text (`working`, `succeeded`, `failed`, `interrupted`). Each line is a button that opens that sub-agent's conversation and selects it in the sub-agent list. When the job ends, those still working show `interrupted`.
- **Sub-agent conversation:** rendered as a job's conversation (messages, `Thinking`, tool rows, its own sub-agents as lines that open theirs), following new text while the sub-agent works, with `Jump to latest` as above.
  - Header: the path from the job, `<job name> › <sub-agent name>`, with every parent sub-agent in between, then the sub-agent's state as icon and text.
  - First entry: the assignment it received, shown as a message labelled with the name of who started it (the job's name, or the parent sub-agent's).
  - Read-only: no `Stop`, no permission card, no notes, no end line.
  - **Disabled message box**, for visual consistency with the job's: pinned at the bottom with the same layout as the **Message box**, textarea and `Send` (`ArrowUp`) both disabled, placeholder `Sub-agents take no messages.`, no `Stop`. The same in Chat and Ask more sub-agent conversations, whatever the state of the sub-agent or of its job, Chat or Ask more conversation, also once they have ended (never the `This job has ended…` line). The textarea is really disabled: out of the tab order and announced as unavailable, as in a queued job.
  - A transcript that is missing or cannot be read shows only `Conversation not available: <reason>.` in secondary text, below the header, with the disabled message box still at the bottom; the sub-agent stays in the list.
- **Notes:** each note appears where it arrived, one secondary line: `StickyNote`, `HH:MM`, the text.
- **Message box:** textarea growing to ~10 lines, placeholder `Message the agent…`; `Enter` sends, `Shift+Enter` new line; `Send` (`ArrowUp`) disabled while empty after trimming. While the job works a message reaches the agent without stopping it (steer).
- **Queued message:** one not delivered yet (a round or permission waits, or omp has not taken it) shows `Clock` + `Queued` under it until delivered; a refused one shows `Not delivered: <reason>.` in the error colour; still queued at the job's end: `Not delivered: the job ended.`
- **Stop:** `Square` button `Stop the agent` beside `Send` while the job is queued, running, waiting or suspended. AlertDialog `Stop <name>?` / `The agent stops at once and every process it started ends.`, `Stop` (destructive) and `Cancel`, focus on `Cancel`.
- **Permission card** (permissions set to `ask`): a box with a warning border headed `omp asks permission`, the compact row of the tool call concerned, then one button per option omp offers, omp's names and order; rejecting options use `outline`. Afterwards it stays read-only with the choice, or `No longer needed.` (voided by the turn's end) or `Cancelled.` (Stop).
- **Queued job:** only `Starting omp…` centred in secondary text, or `Waiting for omp to be ready.` with `Open Settings` while omp is not ready; `Send` disabled.
- **Suspended job:** a secondary line `Weaver stopped; the job continues when its session is reloaded.`; on resume `Session reloaded; the agent continues its work.`
- **End line:** `Finished.` or `Stopped.` (secondary); failed: `TriangleAlert` + `Failed: <reason>.` in the error colour, reasons in plain words (`omp did not answer within 30 s`, `omp exited with code <N>`, `the session could not be resumed`, `the agent refused`, `the agent ran out of tokens`, `the agent reached its turn limit`, a proxy explanation of `requirements/ui#system-certificates`, or omp's message). After an exit, `Show details` opens omp's last error lines in monospace.
- **Finished conversation:** read-only; the message box becomes `This job has ended. Continue in Chat.` with `Open Chat`.
- New agent messages are announced by an `aria-live="polite"` region once per complete message.

## general-chat
- Its own view in every project window, always present, under the view header (`requirements/ui#General`, title `Chat`), with the job conversation rendering (messages, `Thinking`, tool rows, sub-agents, permission cards, queued messages), but no instruction, notes or end line.
- **Sub-agents:** each sub-agent line opens that sub-agent's conversation in place of the chat, as in `## job` (**Sub-agent conversation**), with the header `Chat › <sub-agent name>`, every parent sub-agent in between, and a `Back to Chat` button (`ArrowLeft`) that returns to the chat at the position it had; that header takes the place of the view header, in the same row and at the same height. Meanwhile the chat goes on; `Clear` also returns to the chat.
- Every text of the interface names it `Chat`, never `General`: the sidebar entry, its tooltip, the view's title and the texts below. A request refused because it is not open says `Chat is not open for this project`.
- Empty: centred secondary text `Think with omp about this project. Ask it to write a Proposal or start a job of Weaver when you want one.`
- **Loading:** while the kept conversation loads, centred secondary text `Loading conversation…` in place of the empty text, above any message sent meanwhile, until the history shows. Waiting for omp with omp missing adds the `omp is not installed.` line and `Install omp` at once; while omp is only checking, updating or not connected, the loading text shows alone.
- The message box is always enabled; a message sent while omp starts or reloads shows at once with `Starting omp…` under it until delivered. `Stop` (no dialog) shows during a turn.
- **Clear:** `Eraser` button `Clear` on the right of the header, disabled while empty; a kept conversation that is loading is not empty. AlertDialog `Clear Chat?` / `The conversation is deleted and a new one starts.` (also while loading; during a turn: `The agent's turn stops, the conversation is deleted and a new one starts.`), followed, when Drafts created in Chat exist, by ` Its <n> Draft Proposal(s) are discarded.`, `Clear` (destructive) and `Cancel`, focus on `Cancel`.
- **Waiting for answers:** while a round of Chat waits, the sidebar's Chat entry shows `1` in the warning colour (amber), placed as the Jobs entry's number, with tooltip `Chat is waiting for your answers`; a message sent meanwhile shows `Clock` + `Queued` under it until the round ends. The Jobs entry's number never counts Chat.
- **Started jobs:** a line `Bot` + `Started <job name>` with `Open conversation`, which selects that job in the Jobs view. A refused start: `Weaver did not start <kind>: <reason>.` in the warning colour.
- **Failures:** `omp stopped: <reason>.` in the error colour, then `Your next message starts omp again.` in secondary text. With omp missing: `omp is not installed.` and the `Install omp` button.
