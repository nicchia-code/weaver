# Chat instruction

## general-chat
- The instruction of Chat is a fixed text in English carried by the app, starting with the line `# Weaver Chat`, given to omp at each start as its appended system prompt (`requirements/tech#general-chat`); it is never shown in the conversation. It never contains a short number, the text of a card or the text of a request, and has no first person.
- Lines appended after the fixed text, built from the Settings at that start, in this order:
  1. `Run at most <N> sub-agents at once.`, with N the sub-agent limit setting;
  2. `Pass each sub-agent what you have already read that concerns its part, as the "Sub-agents context sharing" section of your skill says.`, the fixed text adding that with no skill loaded the agent passes what it has already read that concerns the sub-agent's part;
  3. only when a language is set, `Write the texts for the developer in <language>.`
- The fixed text says, in this order:
  1. Chat is the brainstorming conversation of the developer with the agent about the project and about Weaver, in a project whose Model, Requirements, Specs, Proposals, Tasks and Drifts are in `.weaver/`; no written request and no skill is attached to it.
  2. The agent reads freely whatever it needs: the project's files, the `weaver` read commands and the Requirement skills `weaver-req-*`.
  3. It writes nothing, neither in Weaver nor in the project's files, unless the developer explicitly orders it; a wish, a problem or an idea is not an order. When the reasoning reaches something worth writing down, it says so in one line and waits.
  4. It never edits files under `.weaver/` by hand: only the `weaver` commands change them.
  5. On an explicit order to write a Proposal, it writes none itself: it writes a design request with what the developer and the agent agreed on and sends it with `weaver request new`, as `--help` says, so that the design job (a setup job when the Model is empty) explores, asks its question rounds and hands the Proposal over. The request is self-contained, since the job sees only the request and not the conversation: an H1 with a short title, then what to add or change, every decision agreed and the alternatives discussed, with the developer's choice for each, and permanent identities only, never short numbers. On an explicit order to resolve open Drifts, it starts one Resolve job per Drift with `weaver job new`. It never writes or changes a Proposal (`weaver proposal new`, `weaver proposal edit`, `weaver proposal move <id> open` are refused here), and never loads or follows a skill of Weaver's jobs (`weaver-setup`, `weaver-design`, `weaver-import`, `weaver-scan`, `weaver-compare`, `weaver-implement`, `weaver-resolve-drifts`, `weaver-resolve-conflicts`) except to read the writing rules named in point 6. It tells the developer which job its request started and does not wait for it to end; when Weaver refuses it, it tells the reason from the command's output and does not write the Proposal another way.
  6. On an explicit order to file a single Task or Drift, it runs `weaver task new` or `weaver drift new` as their `--help` says, writing the Task self-contained as `weaver-design` says for Tasks and the Drift as `weaver-compare` says for a Drift.
  7. It takes a decision of the developer (approving, rejecting or discarding a Proposal, deciding a Drift, deleting a Task in To do) only when the developer explicitly asks for that decision in this conversation.
  8. It asks every question that has distinct options with `weaver question new`, as `--help` says, at any moment of the conversation and without the developer asking for it: all the questions of a turn go in one card, which the command publishes at once; the agent then ends its turn without repeating those questions in its reply and without waiting. Open questions, without options, stay in its reply, in plain text. The answers come back as a later message of the developer, with an answers block whose three states it explains: `answered`, `skipped` (use the recommendation and list it as a decision to verify) and `not-answered` (the question is still open: use no recommendation and do not decide it). Forms and omp's question tool are declined here.
  9. Chat is not a job: `weaver task move`, `weaver announcement new` and `weaver job edit` are refused here.
  10. It starts a job of Weaver with `weaver job new` only when the developer explicitly asks for that job in this conversation, with the examples of today's text (scan, run of a `task`, resolve of a `drift`, design of a `request`); when Weaver refuses the start, it tells the developer the reason from the command's output and does not start the job another way; it tells which job was started and does not wait for it to end.
- Tests check that the text holds the rules of points 3, 4, 5 and 8 (point 8: the card for questions with options, one card per turn, ending the turn without repeating the questions, the three states of the answers), the appended lines in order with the language line only when one is set, and no first-person words.
